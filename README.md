과제 07 : 인접 행렬과 인접 리스트의 성능 비교

정점 100개짜리 무방향 단순 그래프를 희소(간선 100개) / 밀집(간선 4,000개) 두 가지로 만들고, 각각을 인접 행렬과 인접 리스트로 표현해서 메모리 사용량과 연산별 비교 횟수를 비교했다.

1. 실행 방법
gcc -Wall -Wextra -o graph main.c
./graph          # 기본 seed(2026)
./graph 7        # seed를 바꿔서 실행 가능
간선 목록은 한 번만 랜덤 생성하고, 그 목록으로 행렬/리스트를 둘 다 채웠다. 
프로그램 안에서 모든 (u, v)에 대해 두 표현의 결과가 같은지 검사하고 [check] ... OK로 출력한다. 삽입/삭제 후에도 한 번 더 검사한다.
아래 숫자는 모두 seed 2026 기준 실제 실행 결과다. seed가 바뀌면 단일 측정값은 달라진다.


3. 구현 & 비교 횟수 기준
연산	인접 행렬	인접 리스트
삽입	m[u][v] 확인 1회 후 양쪽 대칭 위치에 1 저장	u의 리스트를 끝까지 훑어 중복 검사(확인한 노드 수), 이후 u, v 양쪽 리스트 맨 앞에 삽입(비교 없음)
삭제	m[u][v] 확인 1회 후 양쪽 0 저장	u의 리스트에서 v를 찾아 삭제 + v의 리스트에서 u를 찾아 삭제 (두 탐색의 확인 노드 수 합)
연결 확인	m[u][v] 확인 1회	u의 리스트를 v를 찾을 때까지(또는 끝까지) 확인한 노드 수
인접 정점 출력	m[u][0..99] 전부 확인 → 항상 100회	u의 리스트 노드 수만큼 (= 차수)
리스트는 단일 연결 리스트이고 삽입은 head 삽입이다.
무방향 그래프라서 u 리스트에 v가 있으면 v 리스트에도 u가 반드시 있기 때문에, 삽입의 중복 검사는 u 쪽만 했다. 반면 삭제는 양쪽 리스트에서 노드를 지워야 하니 양쪽 탐색 횟수를 모두 더했다.
메모리는 그래프 생성 직후(연산 전) 상태에서 sizeof로 계산했고, 난수 생성용 임시 배열(gen)은 제외했다.
행렬 : sizeof(AdjMatrix) = int[100][100] + 간선 수 변수
리스트 : sizeof(AdjList)(head 포인터 100개 + 간선 수) + 노드 수 × sizeof(Node)
64비트 환경 기준으로 sizeof(Node) = 16바이트 (int 4 + 패딩 4 + 포인터 8)



3-1. 메모리 사용량
	인접 행렬	인접 리스트
희소 그래프 (E=100)	40,004 Bytes	4,008 Bytes
밀집 그래프 (E=4,000)	40,004 Bytes	128,808 Bytes


3-2. 단일 측정 (같은 정점 쌍 사용)
Case	구분	삽입	삭제	연결 확인	인접 정점
1	희소 - 행렬	1	1	1	100
2	희소 - 리스트	1	2	1	2
3	밀집 - 행렬	1	1	1	100
4	밀집 - 리스트	76	57	78	77

사용한 정점 쌍

희소 : 삽입 (55, 30), 삭제 (60, 96), 연결 확인 (50, 86), 인접 정점 출력 정점 67 (차수 2)
밀집 : 삽입 (86, 89), 삭제 (68, 71), 연결 확인 (38, 49), 인접 정점 출력 정점 41 (차수 77)
3-3. 참고 : 랜덤 정점 쌍 1,000회 평균

한 번만 뽑은 쌍은 운에 따라 값이 많이 흔들린다. 예를 들어 같은 리스트에서도 쌍에 따라 삭제가 24회일 수도 57회일 수도 있다.
그래서 같은 정점 쌍 1,000개를 두 표현에 똑같이 적용해서 평균도 구했다

	구분	삽입	삭제	연결 확인	인접 정점
희소	행렬	1.00	1.00	1.00	100.00
희소	리스트	2.01	3.95	1.93	1.97
밀집	행렬	1.00	1.00	1.00	100.00
밀집	리스트	78.90	80.36	46.52	79.93


4-1. 희소 그래프 

가능한 간선이 100×99/2 = 4,950개인데 실제는 100개뿐이라 행렬의 대부분이 0이다. 그런데도 행렬은 정점 수만 보고 100×100 공간을 잡기 때문에 40,004 Bytes를 쓴다. 
리스트는 실제로 존재하는 간선(양방향이라 노드 200개)만큼만 저장해서 4,008 Bytes였고, 행렬의 약 1/10 수준이다.

연산 쪽을 보면, 희소 그래프에서는 정점당 평균 차수가 2 정도라서 리스트가 한 번에 확인하는 노드 수도 2개 안팎이다.
평균 비교 횟수가 삽입 2.01, 삭제 3.95, 연결 확인 1.93 정도로 행렬(1회)과 큰 차이가 없다. 반면 인접 정점 출력은 행렬이 무조건 100칸을 다 봐야 하는데 리스트는 평균 1.97회면 끝나서 약 50배 차이가 났다.
결국 희소 그래프에서는 리스트가 메모리도 훨씬 적게 쓰고, 단일 연산 속도 손해도 거의 없고, 인접 정점 탐색은 압도적으로 빠르다.

4-2. 밀집 그래프 

4,000 / 4,950 ≈ 80.8%라서 행렬의 대부분이 1로 채워진다. 이 경우 행렬은 희소일 때와 똑같이 40,004 Bytes인 반면, 리스트는 노드가 8,000개라 128,808 Bytes로 행렬의 약 3.2배나 된다. 
노드마다 정점 번호(int)뿐 아니라 next 포인터와 패딩까지 16 Bytes씩 쓰기 때문에 간선이 많아지면 오히려 손해다.

연산도 마찬가지로 역전됐다. 행렬은 여전히 삽입/삭제/연결 확인이 1회로 일정한데, 리스트는 정점당 차수가 80 정도라 리스트를 한참 훑어야 한다. 평균적으로 삽입 78.9, 삭제 80.4, 연결 확인 46.5회였다.

삽입은 중복 검사로 u의 리스트를 끝까지 보기 때문에 거의 차수(≈80)만큼 든다.
삭제는 u 리스트에서 평균 절반쯤 찾고 v 리스트에서도 절반쯤 찾아서 합치면 대략 차수 정도가 나온다.
연결 확인은 있는 쌍이면 중간쯤에서 멈추고 없는 쌍이면 끝까지 가기 때문에 그 중간값인 46.5 정도가 나왔다.

인접 정점 출력은 행렬 100회, 리스트 약 80회로 거의 비슷해졌다. 밀집 그래프에서는 어차피 이웃이 대부분이라 행렬로 100칸을 훑는 게 낭비가 아니기 때문이다.


5. 한계


비교 횟수는 과제에서 정한 기준(확인한 원소/노드 수)으로 센 값이고, 실제 실행 시간과는 다를 수 있다. 특히 리스트는 노드가 메모리에 흩어져 있어서 캐시 효율 면에서 행렬보다 불리할 수 있는데 이건 측정하지 않았다.
단일 측정은 정점 쌍을 하나만 뽑기 때문에 편차가 크다. 그래서 경향 분석에는 1,000회 평균을 같이 사용했다.
메모리 값은 64비트 환경(포인터 8 Bytes)에서 sizeof로 계산한 값이며, malloc 내부 관리 영역(헤더 등)은 포함하지 않았다.



# 과제 07: 인접 행렬과 인접 리스트의 성능 비교

정점 100개짜리 무방향 단순 그래프를 희소(간선 100개) 및 밀집(간선 4,000개) 두 가지 환경으로 구축하고, 각각을 인접 행렬과 인접 리스트로 표현하여 메모리 사용량과 연산별 비교 횟수를 비교 분석한 보고서입니다.

## 1. 실행 방법

gcc -Wall -Wextra -o graph main.c
./graph          # 기본 seed(2026)
./graph 7        # seed를 바꿔서 실행 가능

- 간선 목록은 1회 무작위 생성하여 동일한 목록으로 행렬과 리스트를 채웠습니다.
- 프로그램 내부에서 모든 (u, v) 정점 쌍에 대해 두 표현의 결과가 일치하는지 검증하고 [check] ... OK 형식으로 출력합니다.
- 본 보고서의 수치는 seed 2026 기준 실제 실행 결과입니다.

## 2. 구현 및 비교 횟수 측정 기준

| 연산 | 인접 행렬 | 인접 리스트 |
| :--- | :--- | :--- |
| 삽입 | m[u][v] 확인 1회 후 양쪽 대칭 위치에 1 저장 | u의 리스트를 끝까지 훑어 중복 검사(확인 노드 수), u/v 리스트 맨 앞에 삽입 |
| 삭제 | m[u][v] 확인 1회 후 양쪽 0 저장 | u 리스트에서 v 탐색/삭제 + v 리스트에서 u 탐색/삭제 (두 탐색 노드 수의 합) |

- 무방향 그래프 특성상 u 리스트에 v가 있으면 v 리스트에도 u가 존재하므로, 삽입 시 중복 검사는 u 쪽만 수행합니다. 반면 삭제 시에는 양쪽 리스트에서 노드를 제거하므로 두 탐색 횟수를 합산합니다.
- 메모리 사용량은 그래프 생성 직후 상태에서 sizeof 연산자로 계산하였습니다. (64비트 환경 기준 노드 1개당 16 Bytes: int 4 + 패딩 4 + 포인터 8)
  - 행렬: sizeof(AdjMatrix) = int[100][100] + 간선 수 변수
  - 리스트: sizeof(AdjList)(head 포인터 100개 + 간선 수) + 노드 수 × sizeof(Node)

## 4. 분석 및 고찰

### 4-1. 희소 그래프 (Sparse Graph)

- 메모리 측면: 정점 100개 기준 가능한 최대 간선 수는 4,950개이나 실제 간선은 100개뿐이므로 행렬 표기 시 대다수 공간이 0으로 채워집니다.
  인접 행렬은 정점 수에 비례해 100x100 공간(40,004 Bytes)을 고정 할당하는 반면, 인접 리스트는 실제 존재하는 간선 수만큼만 노드를 생성하므로 4,008 Bytes를 사용하여 행렬 대비 약 10분의 1 수준으로 메모리를 절약했습니다.
- 연산 성능 측면: 정점당 평균 차수가 약 2 수준이므로 리스트에서 순회하는 노드 수 역시 평균 2개 안팎입니다. 삽입(2.01회), 삭제(3.95회), 연결 확인(1.93회) 연산의 평균 비교 횟수가 행렬(1회)과 큰 차이를 보이지 않았습니다.
특히 인접 정점 출력의 경우 행렬은 항상 100칸을 검사하지만 리스트는 평균 1.97회로 탐색을 완료하여 약 50배의 연산 효율 차이를 보였습니다.
 희소 그래프에서는 인접 리스트가 메모리 효율, 단일 연산 속도, 인접 정점 탐색 등 모든 측면에서 압도적으로 유리합니다.

### 4-2. 밀집 그래프 (Dense Graph)

- 메모리 측면: 간선 수 4,000개로 전체 가능 간선 대비 약 80.8%가 채워진 환경입니다. 인접 행렬은 희소 그래프 때와 동일한 40,004 Bytes를 유지하지만,
- 인접 리스트는 노드가 8,000개로 증가함에 따라 128,808 Bytes를 소비하여 행렬 대비 약 3.2배의 메모리를 사용했습니다. 이는 노드당 정점 데이터 외에 포인터와 메모리 정렬 패딩(16 Bytes)이 추가로 붙기 때문입니다.
- 연산 성능 측면: 정점당 차수가 약 80에 달하므로 리스트 탐색 비용이 급증했습니다.
  - 삽입: 중복 검사 시 u의 리스트를 끝까지 탐색하므로 평균 차수 수치인 78.9회 발생했습니다.
  - 삭제: u와 v 양쪽 리스트에서 각각 평균 절반 위치까지 탐색하여 합산 약 80.36회가 소요되었습니다.
  - 연결 확인: 간선이 존재하는 경우 중간에 탐색이 종료되고 없는 경우 끝까지 진행되므로 그 중간값인 46.52회를 나타냈습니다.
  - 인접 정점 출력: 행렬(100회)과 리스트(약 80회)의 비교 횟수 격차가 크게 줄어들었습니다.
- 소결: 간선 밀도가 높은 그래프에서는 포인터 오버헤드로 인해 인접 리스트의 메모리 및 연산 효율이 행렬보다 저하됩니다.

## 5. 한계점 및 고려사항

- 비교 횟수 측정 기준: 본 실험의 비교 횟수는 과제에서 정의한 단순 원소/노드 확인 수이며 실제 CPU 실행 시간과는 차이가 있을 수 있습니다
   특히 인접 리스트는 동적 할당 노드가 메모리에 파편화되어 존재하므로 캐시 지역성(Cache Locality) 관점에서 배열 기반인 인접 행렬보다 불리할 수 있으나 이 점은 수치에 반영되지 않았습니다.
- 샘플링 편차: 단일 정점 쌍 측정 시 선택된 정점의 차수에 따라 편차가 크게 나타나므로, 정확한 경향성 파악을 위해 1,000회 무작위 샘플링 평균 결과를 함께 반영하였습니다.
- 메모리 계산 범위: 메모리 사용량은 64비트 환경의 sizeof 연산자 기준이며, 동적 메모리 할당(malloc) 시 운영체제가 관리하는 메타데이터 헤더 영역의 크기는 포함하지 않았습니다.
